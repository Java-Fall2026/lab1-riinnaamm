# Лабораторна робота №5: Comparable, Comparator та Stream API

## Пояснення поведінки TreeSet / TreeMap 

Під час ініціалізації `TreeSet` (або `TreeMap`) із власним компаратором (наприклад, порівняння об'єктів `Venue` виключно за місткістю `capacity`), колекція визначає унікальність елементів лише на основі результату методу `comparator.compare(a, b) == 0`, а не через метод `equals()`.

Якщо додати два різні об'єкти з однаковою місткістю (наприклад, `capacity = 200`), компаратор повертає `0`, що сприймається колекцією як збіг ключів. У результаті `TreeSet` вважає другий об'єкт дублікатом першого і не додає його до колекції (розмір залишається `size() == 1`). Це підтверджує, що компаратори для впорядкованих колекцій обов'язково мають бути узгоджені з `equals()` для запобігання втраті даних.
